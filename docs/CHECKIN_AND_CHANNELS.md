# 自动签到与渠道接入状态

核对日期：2026-11-06。协议参考：[dsh-providers-hub](https://github.com/iJetLi/dsh-providers-hub/tree/a5b3cd10dd)（MIT）。下表描述 1.2.1 的源码及安装包能力；此前的 1.2.0 安装包不包含这些签到与新增渠道功能。

## 签到怎么用

在「渠道」页的「签到中心」点击「一键签到」，可手动执行。签到中心同时提供自动执行总开关、执行时间和各渠道开关。关闭自动执行后仍可手动签到；手动执行也遵守渠道开关，并跳过当天已确认领取的账号。签到与聚合轮换分别控制：不参与推理轮换的账号仍可能需要领取每日额度，因此停用聚合不会自动停用签到。

- 默认每天北京时间 09:00、21:00 执行；支持自定义 1–4 个时间。
- 程序启动 30 秒后检查，错过时段会补查当天任务；程序退出或电脑休眠期间不执行。
- 按渠道、账号顺序执行。当前业务日已被上游明确确认的账号会跳过，包括程序重启和手动补签。
- 网络等可重试失败按 5 分钟、15 分钟、1 小时间隔补签，每个时段最多 4 次；下个时段重新检查。凭据失效、需人工核实的结果等待用户处理。
- 显示逐账号结果，区分本次领取、今日已领、活动未开放、需重新登录、需手动处理、请求失败。未知积分数不显示为“+0”。
- 所有请求使用网关当前代理，领取请求不会携带凭据跟随重定向。MiniMax 和 AutoClaw 到期凭据可用对应国内/国际站的 Refresh Token 刷新，其他尚未接通续期的身份需要重新登录。
- 领取记录写入数据目录内的 `checkin.json`，仅保存设置、账号摘要、业务日、结果和重试时间，不存账号昵称、Key、Token 或 Cookie。文件损坏或保存失败时停止领取并在界面提示。

| 渠道 | 状态 | 领取判据 / 限制 |
| --- | --- | --- |
| CodeBuddy 中国版 | 已接入自动领取 | `daily-checkin` 的业务码；重复领取的 HTTP 400 + 10001 归为今日已领 |
| CodeArts | 已接入自动领取 | 只领取 `USER_LOGIN` 活动；按真实请求体签名，必要时补确认；确认失败提示人工核实 |
| LobsterAI | 已接入自动领取 | 活动槽位、今日领取状态及 `check_in` 动作预检后领取，带上游幂等键 |
| TRAE 中国版 | 已接入自动领取 | 先读状态；使用账号独立设备身份。领取响应无积分数时不编造金额；不附带抽奖 |
| Loomy | 已接入每日赠送池初始化 | `/points/first-login`，不是反复补充已消耗额度；旧 `dailyCycleDate` 不记为今日完成 |
| MiniMax 国内 / 国际版 | 已接入自动领取 | `base_resp.status_code` 与 `claim_result` 联合验证，明确使用 `Asia/Shanghai` 时区 |
| AStudio（讯飞） | 已接入自动领取 | 仅处理 `DAILY_REWARD_DIALOG`；先查询待处理弹窗，再确认完成，不执行新人任务 |
| AutoClaw 国内 / 国际版 | 已接入自动领取 | 以 `daily_check_in_completed_on_request` 的明确布尔值判断；缺失字段不当成今日已领 |
| 超级麦吉 / MagiCrew 国际版 | 已接入自动领取 | 独立 `login-gift`，明确验证 `granted`；国际站需组织码，未知领取金额不编造 |
| ZCode | 需手动处理 | 领取需要验证码，自动任务不尝试解决验证码 |
| Qoder 中国版 | 需手动处理 | 本项目的 `qoder` / `qodercn` 是同一条中国版渠道；不能直接套参考插件国际版的活动与设备协议 |
| WorkBuddy 国际版 | 无每日签到接口 | 不再自动发送聊天请求并把它报告为签到成功；活跃请求、每日奖励到账是不同事实 |
| 其他渠道 | 尚未接入可核实的每日领取接口 | 登录赠送、服务端自动发放、一次性新人任务均不冒充每日签到 |

“已接入”表示接口、判定和调度有实现，并通过模拟上游响应的回归测试。各家账号资格、活动是否开放、验证码与风控仍以上游实时结果为准；不能据此宣称所有真实账号已到账。

## 本次新增的渠道

当前界面登记 34 个渠道。以下 5 个渠道条目已实现本机插件导入、手工填写凭据、余额、每日领取、动态模型目录及聚合推理路径；支持多账号选择，以及渠道和模型候选开关。**尚未实现它们自己的浏览器 OAuth / 短信登录向导**，需要先在官方服务或参考插件登录后导入，也可手工填写自己的凭据。

| 渠道 | 条目 ID | 接入要点 |
| --- | --- | --- |
| AStudio（讯飞） | `astudio` | 管理会话 Cookie 与模型 Token 分离，推理端不携带管理 Cookie；累计输出转换为增量，避免重复文本和工具参数 |
| AutoClaw 国内 / 国际版 | `autoclaw` / `autoclawintl` | 两站身份与续期端点独立，支持 Refresh Token；使用钱包当前总余额，不能把流水之和冒充余额 |
| 超级麦吉 / MagiCrew 国际版 | `magicrew` / `magicrewintl` | 管理 JWT、模型网关 Key 与组织码分离；由管理会话按需签发推理 Key，国际站必须带组织上下文 |

- 启动、账号导入或保存后刷新目录，之后每 10 分钟刷新；聚合页手动刷新也会查询新渠道。
- 获取上游完整目录，包含积分模型。MagiCrew 根据模型价格端点读取文字输入积分倍率；其他上游未返回可核实价格时保留未知，不标为免费。
- 多账号目录取并集，只有目录包含该模型的账号才参与该模型请求；每个账号保留自己的推理凭据和组织信息。渠道展示的倍率来自已返回的模型价格，未宣称精确到每个账号套餐。
- 仅在尚未输出内容时尝试同渠道其他账号，已经输出后不从头重试，避免重复回答。
- 有余额但没有精确到期时间时仅表示余额可用，不代表永久或不限量。AStudio 未带时区的到期字符串不臆造时区；星火独立额度池不计入主积分池。

这些接口通过公开源码核对及模拟协议回归测试，**尚未使用真实账号完成新增渠道的领取与模型推理端到端验证**。活动资格与调用权限仍以上游为准。

## 渠道更新中需要避免的误判

- 目录、登录、余额可读，不等于已经有模型转发实现。聚合仍以实际可转发能力决定候选资格。
- 参考项目的 `qoder` 是国际版；本项目历史 `qoder` 是中国版。不能按相同字符串直接替换实现。
- ZCode 新版的客户端版本与官方身份块属于同一代协议，不能只更新版本号。其新推理适配须成套验证。
- Magicrew 锁定永久额度时，余额查询失败不能降级成可随意花费；Baizhi 的后付费钱包同样不能按余额零值简单判死。
- 上游历史文档可能落后于正在执行的代码。Codely 的推理注册应以实际 `index.ts` 为准，而不是只看旧备注。

自动签到实现位于 `internal/zen/chprov/checkin.go`、`reward_channels.go`；调度及本地记账在 `internal/zen/checkin/manager.go`，新增目录及转发适配位于 chprov / gateway 的 `native_channels.go`。
